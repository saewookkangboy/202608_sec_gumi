# Repository Instructions

## 목적

역할을 문서로 분리하고 HITL/HOTL 게이트를 설계한다. (선택) 기존 Node 데모로 동작을 검증한다.

## 역할 경계

- 계획자는 작업과 완료 기준만 정의하고 데이터를 수정하지 않는다.
- 실행자는 근거 ID가 있는 결과만 생성한다.
- 검증자는 결과를 직접 고치지 않고 `PASS`, `REJECT`, `ESCALATE`만 판정한다.
- 최종 우선순위 확정은 사람 승인 전 실행하지 않는다.

## 산출물 (PRD 연속형)

| 경로 | 설명 |
|---|---|
| `agents/*.md` | Planner / Executor / Verifier / A2A / 상태도 |
| `gate-log.md` | HITL 게이트 · HOTL 이관 · 승인 기록 |
| `_sandbox/` | 가상 테스트 전용 |

## 가드레일

- 동일 사유 반려 3회 시 사람에게 이관한다.
- 승인 요청에는 결과, 근거, 검증 판정, 남은 불확실성을 포함한다.
- 자격증명·개인정보를 로그에 기록하지 않는다.
- 완료 전 역할≥3·게이트≥1·HOTL 조건을 확인하고, (선택) `npm test`를 실행한다.

Claude Code는 같은 폴더의 `CLAUDE.md`가 이 파일을 가져온다.
